# Project Restructure Notes

## Why the project was reorganized

The original repository combined completed work, future plans, placeholder documents, and a broad nine-phase roadmap. Several documents also conflicted on the domain name, operating-system version, IP addresses, usernames, and completion status.

The reorganized version separates verified implementation from planned work and reduces the core roadmap to six progressive phases.

## Major changes

- Updated the documented domain to the verified value: `Corp.apexfg.local`.
- Updated the server platform to Windows Server 2025 Evaluation.
- Updated server and client addresses to the verified lab values.
- Reconciled the representative users and their actual group memberships.
- Marked Phase 1 complete and all unimplemented phases as planned.
- Moved screenshots into `evidence/phase-01` and normalized their filenames.
- Replaced the overly broad roadmap with six achievable core phases.
- Moved hybrid Microsoft Entra work to an optional extension.
- Added an evidence-driven completion standard.
- Removed compliance claims that were not supported by a formal assessment.
- Replaced the misleading `SalesData` share concept with the neutral `DepartmentData` design.

## Migration guidance

Use this reorganized directory as the new repository root. Review it locally, then either replace the existing repository contents in a new branch or create a fresh repository. Preserve the original repository until the new links and screenshots have been verified on GitHub.
